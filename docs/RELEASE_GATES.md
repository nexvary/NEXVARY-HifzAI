# سياسة منع إصدار عام غير معتمد — RELEASE GATES

**DEFAULT = BLOCKED.** Debug APK يستخدم فقط لاختبار برمجي أو لإرساله بشكل محدود إلى لجنة مختصة بموافقة القائمين على المراجعة. لا يُقدّم للمستخدم النهائي، ولا على Play Store، ولا على موقع تنزيل عام باعتباره مصحفًا أو محفظًا معتمدًا.

## طبقات القرار
1. **Code QA:** GitHub Actions unit tests/build green + اختبار على جهاز أندرويد فعلي؛ لا تكفي فقط لاختبار القرآن.
2. **Quran Text:** مصدر موثق، حقوق واضحة، hash مستقل، موافقة على الرسم والرواية ونتيجة العرض.
3. **Quran Teaching:** موافقة علماء مختصين على الإخفاء والربط وخطة المراجعة والتغذية الراجعة.
4. **Reciter assets:** أذونات حقوق التلاوات والصور والتسجيلات، واحترام شروط مزود المحتوى.
5. **Privacy and minors:** موافقة المستخدم/ولي الأمر، وعدم تسجيل الصوت دون ضرورة وتوضيح.
6. **Legal jurisdiction:** فحص محامٍ مختص في الدول التي سيطرح بها التطبيق؛ التطبيق لا يثبت الشرعية القانونية بمفرده.
7. **Distribution:** توقيع التطبيق، وثائق التغيير، قابلية الإرجاع، قنوات الدعم، سحب المحتوى الخاطئ، إخطار المراجعين.

## إجراء تقني حالي
- `app/build.gradle.kts` يتضمن مهمة Gradle `blockUnapprovedPublicRelease` ترفض `assembleRelease` و`bundleRelease` و`packageRelease` **دون استثناء** في هذه المرحلة.
- هذا حاجز داخل Gradle فقط؛ لا يمنع أي شخص من استخدام أدوات أخرى أو تعديل المصدر، ولا يُعد بديلًا عن الإشراف والإجراءات المؤسسية.
- يُسمح بفحص `assembleDebug` لتسليم نسخ مراجعة يدوية مع تنبيه واضح بأنها غير معتمدة.
- قبل إزالة حظر الإصدار لاحقًا: PR منفصل يشمل ملفات الدليل الموقّعة فعليًا ونتائج المراجعات؛ مراجعة يدوية مختصة، ثم إعداد توقيع الإصدار في أسرار CI.

## معيار غير مقبول
لا تُفتح بوابة الإصدار لمجرد «نجاح البناء»، أو «كتابة 220 مرحلة»، أو «وجود تقرير AI». لا توجد حالياً شهادات علماء أو موافقات قانونية أو تراخيص إعادة توزيع صوتيات مسجلة في المشروع.
